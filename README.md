# Marstek Metrics

Десктопная программа для Windows, которая следит за станцией **Marstek Venus E 3.0** через локальный Open API. Работает по UDP в той же сети Wi‑Fi, без облака.

- **Сейчас** — потребление дома, импорт/экспорт сети, что делает станция, заряд батареи, режим, CT-счётчик, Wi‑Fi; график мощностей за 1 ч / 6 ч / 24 ч / 7 дней.
- **Расход** — сколько потребил дом сегодня, вчера, за 7 и 30 дней; график и таблица по дням: из сети, в сеть, сколько отдала станция и сколько взяла на заряд.
- **Ошибки** — активные проблемы и журнал: станция не отвечает, CT отключён, слабый Wi‑Fi, низкий заряд, перегрев, запрет заряда/разряда, сброс счётчиков, смена режима и прошивки.

История хранится локально в SQLite, по умолчанию год.

Протокол станции: [docs/open-api.md](docs/open-api.md).

## Подготовка станции

1. Станция привязана в приложении Marstek и подключена к Wi‑Fi.
2. В приложении включён **Open API**, порт по умолчанию `30000`.
3. В роутере за станцией закреплён постоянный IP.
4. Для расчёта расхода дома нужен подключённый CT-счётчик (CT002/CT003).

## Установка (Windows)

Нужен Python 3.11+ с [python.org](https://www.python.org/downloads/). При установке отметьте «Add python.exe to PATH».

```bat
git clone https://github.com/fesh-biz/MarstekMetrics.git
cd MarstekMetrics
py -m venv .venv
.venv\Scripts\activate
pip install -e .
marstek-metrics
```

При первом запуске откроются настройки: нажмите «Найти в сети» или впишите IP станции. Если Windows спросит про брандмауэр — разрешите доступ в **частных сетях**, иначе ответы станции не дойдут.

Запускайте прямо в Windows, не в WSL2: часть прошивок отвечает на порт 30000, а NAT WSL2 такие ответы не пропускает.

### Проверка связи из консоли

```bat
marstek-cli discover
marstek-cli status 192.168.1.50
marstek-cli raw 192.168.1.50 all
```

`raw` печатает ответы станции как есть — их удобно прислать, если что-то показывается неправильно.

### Без станции

Эмулятор Venus E 3.0 (прошивка 150) с реалистичной нагрузкой и потерей 10% пакетов:

```bat
python -m marstek_metrics.mock
```

В настройках программы укажите IP `127.0.0.1`.

### Отдельный .exe

```bat
pip install -e .[dev]
build_exe.bat
```

Получится `dist\MarstekMetrics.exe`.

## Как считается расход

| Величина | Откуда |
|----------|--------|
| Сеть | `EM.GetStatus → total_power`: + берём из сети, − отдаём |
| Станция | `ES.GetStatus → ongrid_power`: + отдаёт в дом, − заряжается |
| Off-grid | `ES.GetStatus → offgrid_power` |
| **Потребление дома** | сеть + станция + off-grid |
| Батарея | `bat_power`, а если его нет (Venus E 3.0) — по балансу мощностей |

Энергия за день — интеграл мощности между замерами. Разрывы больше 5 минут (программа выключена, станция не отвечала) не учитываются, поэтому в таблице есть колонка «Данных за день». Отдача и заряд станции берутся из её собственных счётчиков, если они есть.

Знаки мощностей взяты из документации и опыта сообщества. Если на вашей станции потребление дома выглядит неправдоподобно, пришлите вывод `marstek-cli raw IP all`.

## Опрос

Раз в 30 с программа последовательно запрашивает `ES.GetStatus`, `EM.GetStatus` и `ES.GetMode`, раз в 10 циклов — Wi‑Fi. На каждый запрос — ожидание 10 с и 2 повтора. Чаще 30 с опрашивать не стоит: станция может стать нестабильной.

Данные BMS (`Bat.GetStatus`: температура, запреты заряда/разряда) по умолчанию выключены — на некоторых прошивках этот запрос перезагружает станцию. Включаются в настройках.

## Где лежат данные

`%LOCALAPPDATA%\MarstekMetrics\`: `config.json`, `metrics.db`, `marstek-metrics.log`.

## Разработка

```bat
pip install -e .[dev]
pytest
```

Структура:

```
marstek_metrics/
  protocol.py   UDP-клиент: таймауты, повторы, широковещательный поиск
  device.py     методы Open API
  models.py     нормализация ответов по модели и прошивке
  poller.py     фоновый опрос
  metrics.py    расход по дням
  alerts.py     правила ошибок и предупреждений
  storage.py    SQLite
  mock.py       эмулятор станции
  cli.py        консольная утилита
  gui/          окно на PySide6 + pyqtgraph
```
