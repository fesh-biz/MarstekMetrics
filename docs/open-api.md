# Marstek Device Open API — довідник

Конспект локального API зарядних станцій Marstek Venus для проєкту Marstek Metrics.

**Першоджерело:** [Marstek Device Open API (PDF, Rev 3.1)](https://static-eu.marstekcloud.com/ems/resource/agreement/MarstekDeviceOpenApi.pdf).
Приклади JSON у PDF подекуди з помилками (`"set_result": ture`, переплутані лапки), тому нижче спираємося на таблиці полів і на поведінку реальних пристроїв.

Спостереження щодо прошивок узято з відкритих інтеграцій для Home Assistant:
[taurgis/has-marstek-local-api](https://github.com/taurgis/has-marstek-local-api) (MIT) і
[jaapp/ha-marstek-local-api](https://github.com/jaapp/ha-marstek-local-api).

---

## 1. Підготовка станції

1. Станцію прив'язано в застосунку Marstek і підключено до Wi‑Fi (або Ethernet).
2. У застосунку ввімкнено **Open API** і задано UDP-порт. Типово `30000`, виробник радить діапазон `49152–65535`.
3. Бажано закріпити за станцією статичну IP-адресу в роутері.

Після оновлення прошивки налаштування Open API варто перевірити: воно може скинутися.
Увімкнення Open API може вимкнути частину функцій застосунку, щоб команди не конфліктували.

## 2. Транспорт

- JSON-повідомлення по **UDP**, станція і клієнт в одній локальній мережі.
- Формат схожий на JSON-RPC.

Запит:

```json
{"id": 1, "method": "ES.GetStatus", "params": {"id": 0}}
```

| Поле | Тип | Опис |
|------|-----|------|
| `id` | number / string | Ідентифікатор запиту, обирає клієнт |
| `method` | string | Назва методу, регістр важливий (`Wifi.GetStatus`, а не `wifi.GetStatus`) |
| `params` | object | Параметри; майже завжди `{"id": 0}` — номер екземпляра |

Відповідь:

| Поле | Тип | Опис |
|------|-----|------|
| `id` | number / string | Луна `id` запиту (при помилці розбору може прийти `0`) |
| `src` | string | Назва пристрою, наприклад `VenusC-123456789012` |
| `result` | object | У разі успіху |
| `error` | object | У разі помилки: `code`, `message`, іноді `data` |

Коди помилок:

| Код | Значення |
|-----|----------|
| -32700 | Parse error — невалідний JSON |
| -32600 | Invalid Request |
| -32601 | Method not found — метод не підтримується моделлю/прошивкою (це нормально, не збій зв'язку) |
| -32602 | Invalid params |
| -32603 | Internal error |
| -32000…-32099 | Помилки реалізації |

### Практичні особливості

- Відповіді через Wi‑Fi часто губляться: потрібен тайм-аут ~10–15 с на запит і 2–3 повтори з паузою.
- Запити краще надсилати **послідовно**, з паузою між ними. З пристроєм має працювати **один клієнт** одночасно.
- Опитування частіше ніж раз на 30–60 с може робити станцію нестабільною і рвати зв'язок із CT-лічильником.
- Одна з інтеграцій прив'язує локальний UDP-сокет до того самого порту, що й у станції (30000), — за їхнім досвідом, деякі прошивки відповідають саме на цей порт. Тому з WSL2 (NAT) відповіді можуть не доходити; запускати краще на машині, яка безпосередньо в LAN.

## 3. Виявлення станцій

Широкомовний UDP-запит на порт API:

```json
{"id": 0, "method": "Marstek.GetDevice", "params": {"ble_mac": "0"}}
```

`ble_mac: "0"` — відповідять усі станції; конкретний MAC — лише одна.

## 4. Методи

### Marstek.GetDevice — ідентифікація

Параметри: `ble_mac` (string).

| Поле | Тип | Опис |
|------|-----|------|
| `device` | string | Модель: `VenusC`, `VenusE 3.0`, `VenusA 3.0`, `Venus D` або SKU (`VNSE3-0`, `VNSA-0`, `VNSD-0`, `VNSEM-0`) |
| `ver` | number | Версія прошивки (ціле; від неї залежать одиниці та доступні методи) |
| `ble_mac` | string | Bluetooth MAC — стабільний унікальний ID |
| `wifi_mac` | string | Wi‑Fi MAC |
| `wifi_name` | string | SSID |
| `ip` | string | IP пристрою (може застарівати після зміни DHCP — надійніша адреса відправника пакета) |

### Wifi.GetStatus — мережа

Параметри: `id`. Результат: `wifi_mac`, `ssid`, `rssi` (дБм), `sta_ip`, `sta_gate`, `sta_mask`, `sta_dns`.

### BLE.GetStatus — Bluetooth

Параметри: `id`. Результат: `state` (`connect` / `disconnect`), `ble_mac`.

### Bat.GetStatus — батарея

Параметри: `id`.

| Поле | Тип | Од. | Опис |
|------|-----|-----|------|
| `soc` | number | % | Заряд |
| `charg_flag` | bool | — | Заряджання дозволено |
| `dischrg_flag` | bool | — | Розряджання дозволено |
| `bat_temp` | number | °C | Температура (на старих BMS буває ×10) |
| `bat_capacity` | number | Wh | Залишок |
| `rated_capacity` | number | Wh | Номінальна ємність |

⚠️ На деяких прошивках цей виклик перезавантажує станцію — типово не опитувати.

### PV.GetStatus — сонячні панелі (лише Venus A / D)

Параметри: `id`. Результат: `pv_power`, `pv_voltage` (V), `pv_current` (A), `PV_state` (1 робота / 0 очікування).
На Venus A/D трапляється багатоканальна форма `pv1_…`–`pv4_…`. Потужність каналу 1 на реальних прошивках приходить у **деціватах**: ділити на 10.
На Venus C/E метод повертає `-32601`.

### ES.GetStatus — енергосистема (основна телеметрія)

Параметри: `id`.

| Поле | Од. | Опис |
|------|-----|------|
| `bat_soc` | % | Заряд |
| `bat_cap` | Wh | Ємність |
| `pv_power` | W | Потужність PV |
| `ongrid_power` | W | Потужність на боці мережі |
| `offgrid_power` | W | Потужність на off-grid (EPS) виході |
| `bat_power` | W | Потужність батареї (на Venus E 3.0 fw 150 часто відсутня) |
| `total_pv_energy` | Wh або 0.01 kWh | Залежить від моделі/прошивки |
| `total_grid_output_energy` | Wh | Усього віддано в мережу |
| `total_grid_input_energy` | Wh | Усього взято з мережі |
| `total_load_energy` | Wh | Усього на навантаження |

### ES.GetMode — поточний режим

Параметри: `id` (якщо `0` не відповідає — пробувати `1`).
Результат: `mode` (рядок `Auto`/`AI`/`Manual`/`Passive`/`UPS` **або** число `0–4`), `ongrid_power`, `offgrid_power`, `bat_soc`; у Rev 3.1 також `ct_state`, `a/b/c_power`, `total_power`, `input_energy`, `output_energy` (0.1 Wh).
Дані CT тут бувають нулями при живому лічильнику — джерелом істини вважати `EM.GetStatus`.

### ES.SetMode — зміна режиму

```json
{"id": 1, "method": "ES.SetMode", "params": {"id": 0, "config": {"mode": "Auto", "auto_cfg": {"enable": 1}}}}
```

| `mode` | Конфіг |
|--------|--------|
| `Auto` | `auto_cfg: {enable: 1}` |
| `AI` | `ai_cfg: {enable: 1}` |
| `Manual` | `manual_cfg` — один слот розкладу |
| `Passive` | `passive_cfg: {power, cd_time}` |
| `UPS` | `ups_cfg: {enable: 1}` (прошивка ≥ 150) |

`manual_cfg`:

| Поле | Опис |
|------|------|
| `time_num` | Номер слота: 0–9 (Venus E mini: 0–5) |
| `start_time`, `end_time` | `"HH:MM"` |
| `week_set` | Бітова маска днів: 1 = пн, 3 = пн+вт, 127 = усі дні |
| `power` | Вт; від'ємне — заряджання, додатне — розряджання |
| `enable` | 1 / 0 |
| `manual_set` | Лише Venus E mini: 0 вимк, 1 заряджання, 2 розряджання, 3 авто |

`passive_cfg`: `power` (Вт, знак як вище), `cd_time` — скільки секунд тримати режим.

Відповідь: `{"id": 0, "set_result": true}`. Слоти Manual можна лише записати — прочитати їх назад неможливо. Запис слотів повільний, перша спроба часто відхиляється — потрібні повтори.

### EM.GetStatus — CT-лічильник

Параметри: `id`.
Результат: `ct_state` (0 немає / 1 підключено), `a_power`, `b_power`, `c_power`, `total_power` (W); у Rev 3.1 також `input_energy`, `output_energy` (0.1 Wh → множити на 0.1).

### Системні команди (Rev 3.1, прошивка ≥ 150)

| Метод | Параметри | Призначення |
|-------|-----------|-------------|
| `DOD.SET` | `value` 30–88 (типово 88) | Глибина розряду |
| `Ble.Adv` | `enable` 1 увімк / 0 вимк (у PDF навпаки, вірити прошивці) | Bluetooth-оголошення |
| `Led.Ctrl` | `state` 1 / 0 | Підсвічування панелі |
| `Set.Ver` | `version` | Клас потужності — небезпечно, не використовувати |
| `Reset.Factory` | `type` 1 / 2 | Скидання до заводських — небезпечно, не використовувати |

Методів читання для DOD / LED / BLE-оголошень немає.

## 5. Підтримка за моделями

| Компонент | Venus C / E | Venus A / D | Venus E mini |
|-----------|-------------|-------------|--------------|
| Marstek, Wi‑Fi, BLE, Bat, ES, EM | так | так | так |
| PV | ні | так | ні |
| SYS (DOD/BLE/LED) | fw ≥ 150 | fw ≥ 150 | так |
| UPS | fw ≥ 150 | fw ≥ 150 | fw ≥ 150 |

Venus E 2.0 (HMG-50) відповідає як `VenusE` і, за досвідом спільноти, працює з Open API нестабільно.

## 6. Відомі особливості прошивок

- Одиниці лічильників енергії залежать від моделі та `ver` (Wh / 0.01 kWh / 0.1 Wh) — нормалізувати за профілем прошивки.
- `bat_temp` на старих BMS буває завищена в 10 разів.
- `ES.GetStatus` не відповідає на деяких Venus E v3 (fw 137, 139).
- `ES.GetMode` може повернути режим числом, а не рядком.
- `Bat.GetStatus` на частині прошивок спричиняє перезавантаження.
- Зберігати сирі відповіді та `ver` — знадобиться для розбору проблем.
