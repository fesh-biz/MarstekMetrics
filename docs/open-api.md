# Marstek Device Open API — справочник

Конспект локального API зарядных станций Marstek Venus для проекта Marstek Metrics.

**Первоисточник:** [Marstek Device Open API (PDF, Rev 3.1)](https://static-eu.marstekcloud.com/ems/resource/agreement/MarstekDeviceOpenApi.pdf).
Примеры JSON в PDF местами с опечатками (`"set_result": ture`, перепутанные кавычки), поэтому ниже опираемся на таблицы полей и на поведение реальных устройств.

Наблюдения о прошивках взяты из открытых интеграций для Home Assistant:
[taurgis/has-marstek-local-api](https://github.com/taurgis/has-marstek-local-api) (MIT) и
[jaapp/ha-marstek-local-api](https://github.com/jaapp/ha-marstek-local-api).

---

## 1. Подготовка станции

1. Станция привязана в приложении Marstek и подключена к Wi‑Fi (или Ethernet).
2. В приложении включён **Open API** и задан UDP-порт. По умолчанию `30000`, производитель советует диапазон `49152–65535`.
3. Желательно закрепить за станцией статический IP в роутере.

После обновления прошивки настройку Open API стоит перепроверить: она может сброситься.
Включение Open API может отключить часть функций приложения, чтобы команды не конфликтовали.

## 2. Транспорт

- JSON-сообщения по **UDP**, станция и клиент в одной локальной сети.
- Формат похож на JSON-RPC.

Запрос:

```json
{"id": 1, "method": "ES.GetStatus", "params": {"id": 0}}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | number / string | Идентификатор запроса, выбирает клиент |
| `method` | string | Имя метода, регистр важен (`Wifi.GetStatus`, а не `wifi.GetStatus`) |
| `params` | object | Параметры; почти всегда `{"id": 0}` — номер экземпляра |

Ответ:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | number / string | Эхо `id` запроса (при ошибке разбора может прийти `0`) |
| `src` | string | Имя устройства, например `VenusC-123456789012` |
| `result` | object | При успехе |
| `error` | object | При ошибке: `code`, `message`, иногда `data` |

Коды ошибок:

| Код | Значение |
|-----|----------|
| -32700 | Parse error — невалидный JSON |
| -32600 | Invalid Request |
| -32601 | Method not found — метод не поддерживается моделью/прошивкой (это нормально, не сбой связи) |
| -32602 | Invalid params |
| -32603 | Internal error |
| -32000…-32099 | Ошибки реализации |

### Практические особенности

- Ответы по Wi‑Fi часто теряются: нужен таймаут ~10–15 с на запрос и 2–3 повтора с паузой.
- Запросы лучше слать **последовательно**, с паузой между ними. С устройством должен работать **один клиент** одновременно.
- Опрос чаще раза в 30–60 с может делать станцию нестабильной и рвать связь с CT-счётчиком.
- Одна из интеграций биндит локальный UDP-сокет на тот же порт, что у станции (30000), — по их опыту, некоторые прошивки отвечают именно на этот порт. Поэтому из WSL2 (NAT) ответы могут не доходить; запускать лучше на машине, которая напрямую в LAN.

## 3. Обнаружение станций

Широковещательный UDP-запрос на порт API:

```json
{"id": 0, "method": "Marstek.GetDevice", "params": {"ble_mac": "0"}}
```

`ble_mac: "0"` — ответят все станции; конкретный MAC — только одна.

## 4. Методы

### Marstek.GetDevice — идентификация

Параметры: `ble_mac` (string).

| Поле | Тип | Описание |
|------|-----|----------|
| `device` | string | Модель: `VenusC`, `VenusE 3.0`, `VenusA 3.0`, `Venus D` или SKU (`VNSE3-0`, `VNSA-0`, `VNSD-0`, `VNSEM-0`) |
| `ver` | number | Версия прошивки (целое; от неё зависят единицы и доступные методы) |
| `ble_mac` | string | Bluetooth MAC — стабильный уникальный ID |
| `wifi_mac` | string | Wi‑Fi MAC |
| `wifi_name` | string | SSID |
| `ip` | string | IP устройства (может устаревать после смены DHCP — надёжнее адрес отправителя пакета) |

### Wifi.GetStatus — сеть

Параметры: `id`. Результат: `wifi_mac`, `ssid`, `rssi` (дБм), `sta_ip`, `sta_gate`, `sta_mask`, `sta_dns`.

### BLE.GetStatus — Bluetooth

Параметры: `id`. Результат: `state` (`connect` / `disconnect`), `ble_mac`.

### Bat.GetStatus — батарея

Параметры: `id`.

| Поле | Тип | Ед. | Описание |
|------|-----|-----|----------|
| `soc` | number | % | Заряд |
| `charg_flag` | bool | — | Заряд разрешён |
| `dischrg_flag` | bool | — | Разряд разрешён |
| `bat_temp` | number | °C | Температура (на старых BMS бывает ×10) |
| `bat_capacity` | number | Wh | Остаток |
| `rated_capacity` | number | Wh | Номинальная ёмкость |

⚠️ На некоторых прошивках этот вызов перезагружает станцию — по умолчанию не опрашивать.

### PV.GetStatus — солнечные панели (только Venus A / D)

Параметры: `id`. Результат: `pv_power`, `pv_voltage` (V), `pv_current` (A), `PV_state` (1 работа / 0 ожидание).
На Venus A/D встречается многоканальная форма `pv1_…`–`pv4_…`. Мощность канала 1 на реальных прошивках приходит в **деци-ваттах** (делить на 10).
На Venus C/E метод возвращает `-32601`.

### ES.GetStatus — энергосистема (основная телеметрия)

Параметры: `id`.

| Поле | Ед. | Описание |
|------|-----|----------|
| `bat_soc` | % | Заряд |
| `bat_cap` | Wh | Ёмкость |
| `pv_power` | W | Мощность PV |
| `ongrid_power` | W | Мощность на стороне сети |
| `offgrid_power` | W | Мощность на off-grid (EPS) выходе |
| `bat_power` | W | Мощность батареи (на Venus E 3.0 fw 150 часто отсутствует) |
| `total_pv_energy` | Wh или 0.01 kWh | Зависит от модели/прошивки |
| `total_grid_output_energy` | Wh | Всего отдано в сеть |
| `total_grid_input_energy` | Wh | Всего взято из сети |
| `total_load_energy` | Wh | Всего на нагрузку |

### ES.GetMode — текущий режим

Параметры: `id` (если `0` не отвечает — пробовать `1`).
Результат: `mode` (строка `Auto`/`AI`/`Manual`/`Passive`/`UPS` **или** число `0–4`), `ongrid_power`, `offgrid_power`, `bat_soc`; в Rev 3.1 также `ct_state`, `a/b/c_power`, `total_power`, `input_energy`, `output_energy` (0.1 Wh).
Данные CT здесь бывают нулями при живом счётчике — источником истины считать `EM.GetStatus`.

### ES.SetMode — смена режима

```json
{"id": 1, "method": "ES.SetMode", "params": {"id": 0, "config": {"mode": "Auto", "auto_cfg": {"enable": 1}}}}
```

| `mode` | Конфиг |
|--------|--------|
| `Auto` | `auto_cfg: {enable: 1}` |
| `AI` | `ai_cfg: {enable: 1}` |
| `Manual` | `manual_cfg` — один слот расписания |
| `Passive` | `passive_cfg: {power, cd_time}` |
| `UPS` | `ups_cfg: {enable: 1}` (прошивка ≥ 150) |

`manual_cfg`:

| Поле | Описание |
|------|----------|
| `time_num` | Номер слота: 0–9 (Venus E mini: 0–5) |
| `start_time`, `end_time` | `"HH:MM"` |
| `week_set` | Битовая маска дней: 1 = пн, 3 = пн+вт, 127 = все дни |
| `power` | Вт; отрицательное — заряд, положительное — разряд |
| `enable` | 1 / 0 |
| `manual_set` | Только Venus E mini: 0 выкл, 1 заряд, 2 разряд, 3 авто |

`passive_cfg`: `power` (Вт, знак как выше), `cd_time` — сколько секунд держать режим.

Ответ: `{"id": 0, "set_result": true}`. Слоты Manual можно только записать — прочитать их обратно нельзя. Запись слотов медленная, первая попытка часто отклоняется — нужны повторы.

### EM.GetStatus — CT-счётчик

Параметры: `id`.
Результат: `ct_state` (0 нет / 1 подключён), `a_power`, `b_power`, `c_power`, `total_power` (W); в Rev 3.1 также `input_energy`, `output_energy` (0.1 Wh → умножать на 0.1).

### Системные команды (Rev 3.1, прошивка ≥ 150)

| Метод | Параметры | Назначение |
|-------|-----------|------------|
| `DOD.SET` | `value` 30–88 (по умолчанию 88) | Глубина разряда |
| `Ble.Adv` | `enable` 1 вкл / 0 выкл (в PDF наоборот, верить прошивке) | Bluetooth-реклама |
| `Led.Ctrl` | `state` 1 / 0 | Подсветка панели |
| `Set.Ver` | `version` | Класс мощности — опасно, не использовать |
| `Reset.Factory` | `type` 1 / 2 | Сброс к заводским — опасно, не использовать |

Методов чтения для DOD / LED / BLE-рекламы нет.

## 5. Поддержка по моделям

| Компонент | Venus C / E | Venus A / D | Venus E mini |
|-----------|-------------|-------------|--------------|
| Marstek, Wi‑Fi, BLE, Bat, ES, EM | да | да | да |
| PV | нет | да | нет |
| SYS (DOD/BLE/LED) | fw ≥ 150 | fw ≥ 150 | да |
| UPS | fw ≥ 150 | fw ≥ 150 | fw ≥ 150 |

Venus E 2.0 (HMG-50) отвечает как `VenusE` и, по опыту сообщества, работает с Open API нестабильно.

## 6. Известные причуды прошивок

- Единицы счётчиков энергии зависят от модели и `ver` (Wh / 0.01 kWh / 0.1 Wh) — нормализовать по профилю прошивки.
- `bat_temp` на старых BMS бывает завышен в 10 раз.
- `ES.GetStatus` не отвечает на некоторых Venus E v3 (fw 137, 139).
- `ES.GetMode` может вернуть режим числом, а не строкой.
- `Bat.GetStatus` на части прошивок вызывает перезагрузку.
- Хранить сырые ответы и `ver` — пригодится для разбора проблем.
